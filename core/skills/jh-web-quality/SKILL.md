# 작은 웹 앱을 실제로 마무리하기

기존 앱이면 기존 스택을 유지한다. 새 로컬 MVP이고 외부 서비스가 필요 없다면 이미 있는 런타임과 최소 의존성부터 제안한다. 프레임워크·DB·로그인을 무조건 추가하지 않는다.

- 고객 관리라면 추가/조회/수정/삭제/검색, 이름·이메일 검증, 중복·빈 데이터·실패 표시를 실제 동작으로 확인한다.
- 사용자 입력을 innerHTML에 넣지 않는다. 접근 가능한 label/버튼, 키보드 조작, 좁은 화면을 고려한다.
- 로컬 서버는 loopback에 바인딩하고, 민감정보/실제 고객 데이터 없이 합성 데이터로 테스트한다. 로컬 MVP를 공개 서비스로 소개하지 않는다.
- 정상 경로뿐 아니라 잘못된 JSON/입력·중복·없는 ID·저장 재시작을 검증한다. 브라우저를 실행하지 않았다면 화면 동작과 접근성 검토는 NOT_RUN으로 구분한다.
- README에는 실제 명령, 접속 주소, 저장 위치, 종료·재시작 방법, 공개 운영 전 필요한 인증·백업·HTTPS를 적는다.

테스트 후 `skills record jh-web-quality --result APPLIED --note "실제로 적용한 내용"`을 기록한다. 웹 앱에서 차트/지표 설계가 필요할 때만 기존 dashboard-builder를 추가로 검색한다.
