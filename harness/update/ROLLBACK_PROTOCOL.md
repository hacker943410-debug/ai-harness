# Harness rollback
Stop product feature changes on migration failure. Record error/partial actions, project root, plan/checkpoint and original binding hashes. `node scripts/harness-v6.mjs rollback --project <path>` restores Harness-managed binding snapshot, including absent versus present files and adapter/config/state/transition bytes.
Before rollback verify current files match applied expectations; post-apply user drift is conflict and must be preserved. Never recursively replace product repository or execute arbitrary recovery shell text. Use newest valid transaction recovery evidence; an invalid/incomplete snapshot blocks claimed recovery.
After restore compare hashes and version/state/managed markers/unmanaged bytes, run diagnose and explicitly configured build/critical tests, then report restored/failed/unknown evidence. Failed restore remains BLOCKED; retain checkpoint and actionable next step.
Product/database rollback is separate: classify EASY/MODERATE/HARD/IRREVERSIBLE, establish verified backup/restore/forward recovery as applicable and use explicit migration decision. Harness binding snapshot alone cannot restore product data. No successful rollback claim without bytes/evidence; no automatic resume after failed regression.
