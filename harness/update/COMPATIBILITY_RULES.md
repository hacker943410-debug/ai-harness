# Compatibility and local preservation
Inventory project rules, domain/custom Skills, verified command argv, deployment/security/company constraints, model overrides and local JIT policies. Keep current 26 policies, disabled Jev and Skill precedence; Layer A source / B shared runtime / C project bindings remain separate.
Matrix: Component | Current | Target | Compatibility | Action | Risk | Evidence. Actions KEEP/EXTEND/MERGE/REPLACE/DEPRECATE; classifications UPSTREAM/LOCAL/MERGED/CONFLICT. Preserve unknown user fields and unmanaged adapter bytes.
Three-way concept compares old upstream + local + new upstream. Use recorded baseline where available; absent baseline or changed managed block is conflict, not automatic upstream overwrite. Multiple/unpaired markers block mutation. Only AI-HARNESS markers in AGENTS.md/CLAUDE.md/GEMINI.md are managed; no product file or custom Skill rewriting.
Supported source versions must match manifest declaration and actual tested adapters; legacy detection is not proof of all-version migration support. Release declaration lists supported_from, known_conflicts, required/optional migration, deprecated and removed. New rules affect new/current scoped code; historical refactor needs benefit/cost/risk/tests/rollback/user decision.
Framework migration checks breaking/deprecated/peer/runtime/build/type/test/deploy/security contracts through P15. DB additive/transformative/destructive uses P16; auth/security uses P17 and decision gate. Product migrations are separate from Harness binding updates.

For legacy v5.1 managed instructions, only exact normalized upstream templates from `legacy/PROJECT_INIT_v5_1.md` migrate automatically. Added local text becomes a conflict. Non-UTF8 instruction bytes are preserved and require a reversible encoding decision. Legacy YAML remains an ACTIVE_LOCAL_CONSTRAINTS reference in project configuration, which the bridge requires the agent to read before routing. No repeated nesting of historical YAML during subsequent updates.
