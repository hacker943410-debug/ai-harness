# Version detection
Read HARNESS_VERSION as source release version; require agreement with harness/manifest.yaml harness.version and POLICY_INDEX.yaml harness_version. Manifest is JSON serialization, valid YAML 1.2, parsed without package dependency. It supplies schema/capabilities/required runtime/project files/supported source versions/benchmark schema/compatibility.
Inspect .ai/harness-project.json and .ai/harness-state.json for local pin/current rule set; legacy .ai/harness.yaml/.ai/HARNESS.md are evidence of existing adoption, not permission to overwrite. Distinguish UPSTREAM VERSION, LOCAL VERSION and LOCAL CUSTOMIZATION. A missing/ambiguous legacy version is UNKNOWN and requires conservative plan.
Use `node scripts/harness-v6.mjs inspect --project <path>`; report HARNESS_CURRENT, HARNESS_VERSION_MISMATCH, HARNESS_MIGRATION_IN_PROGRESS, HARNESS_UPDATE_DEFERRED or HARNESS_REPAIR_REQUIRED as evidenced. Different initialized_with records alone are not an error. Conflicting source versions block trusted upgrade until reconciled. Never fetch/execute unpinned code silently; release tag/revision and provenance belong in evidence.
