# Self-contained install/update procedure
One request (“AI Harness v6.0으로 업데이트해줘”) invokes the whole flow; users need not paste bootstrap instructions.
1. Run inspect and route from scripts/harness-v6.mjs for project path and original one-line request. Detect install/adoption/update/migration/repair, source/local versions, mode/state/update class/risk, custom rules and pending transition.
2. Brief current state, goal, effects, safe timing and recommendation. Active implementation H2/H3 normally defers to checkpoint/next phase. HOTFIX/active deployment/data conversion defers major updates. Minimal HARNESS_BLOCKER fix must record reason, scope, rollback and verification.
3. Inventory/gap/compatibility, carry-forward commands/Skills/preferences/decisions and protect product bytes. Create recoverable checkpoint; freeze only when transitioning. Use relevant adoption/transition protocol.
4. `node scripts/harness-v6.mjs plan --project <path> --request '<one line>' --out <plan.json>` creates reviewable dry-run plan/transition description with binding byte snapshots and expected hashes. Inspect actions/conflicts before apply. It does not run discovered commands.
5. Resolve material conflicts/irreversible choices using decision-gate.md. Already-authorized safe additive work proceeds. `node scripts/harness-v6.mjs apply --plan <plan.json>` revalidates drift, snapshots and writes only managed bindings. Conflicts/drift stop before mutation; failures require recovery verification.
6. Run diagnose and configured verify, then audit carried goal/phase/acceptance/baseline/custom bytes/product hashes. Backfill missing critical release gates without replaying completed phases. Independent review evaluates actual diff/evidence.
7. Resume only after required Harness/regression evidence, audit and effective-rule timing are clear. Record benchmark actual time/calls/retries/manual decisions/conflicts/repairs/rules reused/files/resume, with token estimator separated from provider tokens.
8. Failure uses ROLLBACK_PROTOCOL.md. Report files/result/evidence/limitations and next step; never claim production or whole v6 completion from install success.
Project artifacts: .ai/harness-project.json (binding/configured argv), .ai/harness-state.json (goal/phase/acceptance/decisions/evidence/deferred target), .ai/transition-manifest.yaml (JSON-compatible YAML). Adapter blocks stay thin. Shared MCP auth/registration remains separate existing Layer B workflow, not automatic product installer side effect.

The source downloader stages a separate candidate at major version boundaries and preserves the old shared source HEAD. Pin the candidate commit/version before a project transition. `apply` recomputes and compares plan semantics, refuses old journal reuse and records every intermediate write hash before mutation for interrupted rollback. Benchmark metrics cover the Harness transaction; independent project release review remains a separate required gate.
