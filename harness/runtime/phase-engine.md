# Phase engine
The canonical lifecycle is 00 INTAKE → 01 DISCOVERY → 02 REQUIREMENTS → 03 ARCHITECTURE → 04 ACCEPTANCE → 05 UX_UI_DESIGN → 06 VISUAL_VERIFICATION → 07 VERTICAL_SLICE → 08 FEATURE_IMPLEMENTATION → 09 AUTOMATED_VERIFICATION → 10 INDEPENDENT_REVIEW → 11 RELEASE_VERIFICATION → 12 DEPLOY → 13 PRODUCTION_VERIFICATION → 14 RETROSPECTIVE → 15 HARNESS_BENCHMARK_LEARNING.
States: NOT_STARTED, READY, IN_PROGRESS, WAITING_USER, BLOCKED, VERIFYING, FAILED, PASS, DEPLOYED, VERIFIED_PRODUCTION. Mode profiles may combine phases, never remove acceptance, verification, review or applicable deployment responsibilities.
Each phase contract records GOAL, INPUT, SCOPE, NON_GOALS, CONSTRAINTS, DEPENDENCIES, DECISIONS, IMPLEMENTATION_PLAN, ACCEPTANCE_CRITERIA, VERIFICATION_METHOD, EXPECTED_EVIDENCE, RISKS, ROLLBACK, STOP_CONDITIONS, OUTPUT, HANDOFF and actual EVIDENCE. Critical fields GOAL, ACCEPTANCE_CRITERIA, VERIFICATION_METHOD and EVIDENCE are required before PASS.
Use `node scripts/harness-v6.mjs phase --project <path> --phase <ID> --contract <json>` for machine gates; its validated JSON schema is the executable authority. A prose review cannot bypass it.

Machine phase IDs run `00_INTAKE` through `15_HARNESS_BENCHMARK`; full conceptual phase names above describe responsibilities. Contract JSON includes `status`, `goal`, `acceptance_criteria`, `verification_method`, `evidence`; optional N/A requires `required:false` and a specific `reason` (at least 12 characters, not a generic skip). Evidence uses artifact references or structured actual command records. Production evidence must identify production environment, PASS and `simulated:false`; ordinary artifact strings cannot certify production. State retains `phases[phaseId]`, `current_phase` and `next_action`. Resume validation requires complete snake_case transition fields and six evidence-bearing PASS gates: `harness_validation`, `transition_audit`, `build_baseline`, `test_baseline`, `critical_regression`, `benchmark`.
Discovery inspects structure, architecture, DB/API/auth/state/design/dependencies/tests/build/deployment/CI/rules without product edits. Requirements define functional/nonfunctional behavior, flow, edge cases, operational/security constraints and non-goals. Architecture fixes boundaries, data/API contracts, auth/validation/errors/logging/observability/deploy/rollback. Acceptance maps each criterion to an executable check. Design covers loading/empty/error/success/disabled/denied/offline and responsive states. Visual uses render→screenshot→DOM→compare→fix→render; unavailable browser evidence is UNKNOWN. Vertical slice proves UI/API/DB/auth/validation/errors/test/deployment together. Implementation uses small scoped units.
Failed predecessor, missing acceptance, failed verification, critical review finding or failed production check blocks downstream completion. N/A must explain applicability; historical phases carried forward by transition audit are not rerun automatically.

CLI evidence records artifact digests and product fingerprints, rechecks prerequisite artifacts (including compressed gates), rejects stale product verification and invalidates later gates after a revised earlier contract. Pure engine tests validate shapes; CLI validates actual local artifacts. Existing evidence without digests must be backfilled before dependent release gates. Phase-state writes reject credential values.
