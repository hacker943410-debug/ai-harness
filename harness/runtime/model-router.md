# Model and reasoning router
Resolve model choices from the active runtime catalog, never hardcode provider names into policy. economy corresponds to FAST, balanced to BALANCED, frontier to STRONG; MAX is exceptional escalation rather than default model selection.
economy/LOW: search, extraction, version detection, inventory, mechanical edit, straightforward checks. balanced/MEDIUM: ordinary implementation, bounded debug, tests, UI and benchmark analysis. frontier/HIGH: architecture, security, auth/payment, risky migration, compatibility decisions, complex debug, independent release review and integration when justified.
Start at lowest capable tier, escalate once on evidence of inadequate capability or high-risk boundary. MAX reasoning requires unresolved HIGH work/high failure cost or measured benefit. Length alone is not escalation evidence. Missing models means use best available and report fallback.
Delegate only bounded independent work with net savings; default at most three workers and avoid same file/schema/API decisions. Distill goal, constraints, refs, output contract and validation; use minimum context fork. Primary retains scope, safety, integration and final answer. Honor runtime/project prohibition on delegation. Log tier/reason/escalation/high-reasoning use and compare measured quality/cost.
