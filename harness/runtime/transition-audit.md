# Transition audit and backfill
Compare checkpoint to candidate installed bindings. Inventory completed/current phases, goal/acceptance/architecture decisions, commands/test baseline, local rules/Skills/security/deployment/model preferences, required files and new critical gates.
Classify every difference: CARRY_FORWARD, ADOPT_NOW, ADOPT_NEXT_PHASE, DEFER, MIGRATION_REQUIRED or CONFLICT. Record evidence and effective phase for each. Old phase evidence remains valid unless actual scope/rule incompatibility invalidates it; never restart finished discovery/design just because a new version exists.
Backfill only applicable release-critical security review, independent review, regression baseline, production verification, critical data validation and rollback checks. Give each missing gate owner, scope, due-before-release point and evidence requirement. Unresolved critical backfill blocks release.
Resume requires Harness validation, complete audit, known build/test baseline, critical regression PASS, restored current goal/phase/next task and clear new-rule timing. Record RESUMING then IN_PROGRESS after first successful resumed task. Lost goal/phase/acceptance/baseline/custom rule, unexplained build failure, critical regression, unavailable rollback or incomplete manifest means not complete.
Transition benchmark captures work lost, completed phase rework, repairs/conflicts/manual decisions, elapsed time/tokens/files/rules reused or replaced and resume result. Simulated resume is labeled SIMULATION, not production success.
