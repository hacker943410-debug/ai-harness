# Beginner mode and incremental wizard
BEGINNER_MODE defaults ON for initial install/adoption/new project; change to expert only by explicit preference. Preserve preference across updates and all four modes.
After executable inspect/diagnose, ask only the next missing material question. First establish what to build/change, who uses it and primary flow. Then ask personal/internal/customer use and scale/mobile/auth/payment/sensitive data/external API only when relevant. Finally explain local/internal/public deployment and provider alternatives when an actual deployment choice is due. Infer known facts from repository evidence rather than asking user to repeat them.
Unknown answers get explained reversible defaults: local development, minimal scaffold, retain current framework/build/deployment, no new paid service or data migration. Security/payment/public exposure decisions require briefing; never silently default them. Record ASSUMPTION with revisit trigger.
Guide install→environment diagnosis→init→goal→requirements→architecture→acceptance→UI→vertical slice→implementation→verification→review→release→deploy→production→retrospective→benchmark. Existing application uses maintenance/adoption flow; no automatic rewrite.
Diagnosis covers Git/runtime/package manager/CLI/env-variable names/repository access/build/test/lint/type/dev server/production build/deployment/DB/migration/browser capability. Explain PASS/FAIL/NOT_CONFIGURED/UNKNOWN using actual evidence. Resolve blocking environment issues before affected feature work; propose capabilities only for demonstrated gaps.
