# ㉔ 코드베이스 운영체계 지침 v1

## Codebase Operating System Policy

### 기능·파일·심볼·의존성·영향도·테스트·아키텍처를 AI가 빠르게 탐색하고 최소 범위만 수정하기 위한 코드베이스 지도 운영 지침

Version: 1.0

---

# 0. 목적

이 지침은 AI Agent가 개발 작업을 받을 때마다 Repository 전체를 처음부터 뒤지거나, 파일명만 보고 추측하거나, 관련 없는 코드를 대량으로 읽는 문제를 방지한다.

대표적인 실패:

```text
기능 위치를 몰라 Repository 전체 검색

파일명만 보고 Target 추측

실제 실행 흐름을 확인하지 않고 수정

같은 Feature를 Session마다 재탐색

관련 Test를 찾지 못함

Shared Code 영향도를 확인하지 않음

오래된 문서를 실제 코드보다 신뢰

Line Number를 영구 Reference로 사용

Code Map이 오래됐는데 그대로 사용

한 Feature 수정에 필요 없는 파일 수십 개 읽음

Subagent마다 동일한 위치를 다시 검색

기능과 파일의 관계를 사람이 기억해야 함
```

이를 방지하기 위해 Codebase를 단순 파일 모음이 아니라 다음과 같은 **탐색 가능한 운영 지도**로 취급한다.

```text
USER FEATURE

↓

FEATURE MAP

↓

PRIMARY SYMBOL

↓

CALL / DATA FLOW

↓

DIRECT DEPENDENCIES

↓

IMPACT MAP

↓

RELATED TESTS

↓

MINIMUM TARGET FILES

↓

CHANGE

↓

MAP UPDATE
```

최종 목표:

> AI가 “어디에 있는지 모르니 전체 Repository부터 읽는 방식”에서 벗어나, 기능 단위로 필요한 코드에 곧바로 접근하고 실제 Source를 확인한 뒤 최소 범위만 수정하게 한다.

# 1. 최상위 원칙

> Repository 전체를 이해한 뒤 코딩하는 것이 목표가 아니다.

목표는:

```text
현재 Task를 정확하게 처리하기 위해 필요한
최소한의 코드 구조를 충분히 이해하는 것
```

이다.

```text

```

---

# 3. 역할

각 Map은 서로 다른 질문에 답한다.

```text
Architecture Map
→ 시스템이 어떻게 나뉘어 있는가?

Repository Map
→ 어떤 Directory가 어떤 책임을 가지는가?

Feature Map
→ 사용자 기능이 어디에 구현돼 있는가?

Symbol Map
→ 정확한 함수/Class/Component는 무엇인가?

Code Graph
→ 무엇이 무엇을 호출/사용하는가?

Impact Map
→ 이것을 바꾸면 어디에 영향이 가는가?

Convention Map
→ 이 프로젝트에서는 어떻게 구현하는가?

Test Map
→ 무엇으로 검증하는가?
```

---

# 4. Source of Truth 우선순위

현재 시스템 상태를 판단할 때 기본 우선순위:

```text
1. 실제 Source Code

2. Runtime Behavior / Executed Tests

3. Current Generated Symbol / Graph Index

4. Current Feature Map

5. Architecture / Feature Documentation

6. Historical Documentation

7. AI Inference
```

---

# 339. 압축 Core 지침

```text
코드베이스 운영체계 CORE

1. 비단순 코드 변경 전에 사용자 요청을 안정적인 Feature ID 또는 명확한 구현 기능으로 식별한다.
2. 전체 Repository를 먼저 읽지 말고 Feature Map, Route, Symbol, API 등 가장 직접적인 Index부터 사용한다.
3. Map과 문서는 실제 Source에 도달하기 위한 Navigator이며 실제 Source Code가 최종 현재 상태의 Source of Truth다.
4. 영구 Reference는 가능한 한 line number보다 file#symbol 같은 안정적인 Symbol Reference를 사용한다.
5. Feature Map은 사용자 기능을 UI, API, Backend, Data, Tests, Related Decisions와 연결한다.
6. Target Symbol을 수정하기 전에 실제 Source와 필요한 direct caller/callee, data contract, relevant tests를 읽는다.
7. Context는 Target → Direct Dependency → Impact 순으로 점진적으로 확장하며 현재 Task에 필요 없는 Repository 영역을 로드하지 않는다.
8. Shared 또는 cross-feature Symbol을 변경하기 전에 known consumers, tests, local alternative, impact radius를 확인한다.
9. Existing Project Convention을 확인한 후 구현하고 AI의 선호 Pattern을 이유 없이 새로 도입하지 않는다.
10. 관련 Test를 구현 마지막이 아니라 Target 선정 단계에서 가능하면 함께 식별한다.
11. Feature Map lookup이 실패하면 Route → Symbol/UI → API → Backend → Data 흐름으로 실제 실행 경로를 추적하여 Feature를 식별한다.
12. Map이 누락됐다고 첫 grep 결과를 바로 수정하지 않는다.
13. Generated Map과 Symbol Index에는 git/source freshness metadata를 유지하고 Stale 가능성을 확인한다.
14. Generated 파일은 직접 수정하지 말고 generator/source mapping을 수정한 뒤 재생성한다.
15. 구조, Route, Symbol, Feature relation이 변경된 경우에만 필요한 Map을 갱신하고 단순 Logic 변경에 문서 작업을 과도하게 추가하지 않는다.
16. Multi-Agent 탐색은 UI/API/Test 등 독립 Scope로 분할해 동일 Repository 영역의 중복 탐색을 줄인다.
17. Semantic Search와 AI inference 결과는 Candidate이며 정확한 Symbol/Source 확인 전 Fact로 승격하지 않는다.
18. Code Map에서 Security, Migration, External Dependency 등 새로운 Boundary가 발견되면 Instruction Router가 해당 전문 Policy를 JIT 활성화한다.
19. Checkpoint/Handoff에는 전체 Repository 정보가 아니라 Feature ID, primary symbols, important flow, tests, impact, freshness만 보존한다.
20. Codebase OS의 성공은 Map 크기가 아니라 Feature를 더 적은 탐색·Context·오류로 정확한 Source와 Test까지 연결하는 능력으로 평가한다.
```

# 340. Final Principle

대규모 Repository에서 AI에게 가장 나쁜 명령 방식은:

```text
"전체 코드를 잘 파악해서 알아서 수정해."
```

이다.

Repository가 커질수록 AI는:

```text
READ EVERYTHING
```

이 아니라:

```text
KNOW WHERE TO LOOK
```

할 수 있어야 한다.

따라서 이상적인 흐름은:

```text
WHAT FEATURE?

↓

WHERE IS ITS MAP?

↓

WHAT SYMBOL IS PRIMARY?

↓

HOW DOES DATA FLOW?

↓

WHO DEPENDS ON IT?

↓

WHAT TEST PROTECTS IT?

↓

WHAT IS THE MINIMUM CHANGE?

↓

VERIFY

↓

UPDATE THE MAP ONLY IF STRUCTURE CHANGED
```

이다.

Codebase OS의 목적은 AI가 전체 Codebase를 항상 머릿속에 넣는 것이 아니다.

> **전체 Codebase를 외우지 않아도 필요한 기능의 정확한 위치와 관계를 즉시 다시 찾을 수 있게 만드는 것**이다.

그리고 가장 중요한 원칙은:

> **AI의 Context Window를 Repository 저장소로 사용하지 말고, Repository 자체에 AI가 탐색할 수 있는 지도를 만든다.**
