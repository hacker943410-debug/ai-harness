# 회사 Word 양식 패치와 검증

이 기능은 사용자가 보관한 회사 DOCX에서 양식을 재사용하는 로컬 스킬이다.
`회사용 Word 양식으로 적용해서 만들어줘`라는 요청을 처리한다. 회사 원본,
로고·담당자·업무 내용과 실제 출력물은 공개 배포에 포함하지 않는다.

## 저장 구조

| 위치 | 내용 |
|---|---|
| `core/skills/jh-company-word/` | 공개되는 일반 스킬, 표준 라이브러리 Python 도구, Word 출력 도구, 품질 규칙 |
| 프로젝트 `.ai/company-word.json` | 우선 적용할 로컬 프로필 경로 |
| Codex home 또는 사용자 `.agents/company-word.json` | 프로젝트 지정이 없을 때 적용할 개인 기본 프로필 |
| 로컬 프로필 `reference.docx` | 수정하지 않은 원본과 고정 SHA-256 |
| 로컬 프로필 `profile.json` | 구역·페이지·문단·표·패키지·입력 슬롯·허용된 머리말 문구 |
| 로컬 프로필 `artifact.md`와 렌더 이미지 | 수치로 추출한 양식, 구성 요소, 시각 비교 근거 |

원본의 내용과 문서 목적은 구분한다. 회사 양식은 재사용하지만 원본의 목차,
담당자, 승인 이력과 업무 결과가 모든 새 문서에 따라 들어가지는 않는다.
기본 생성기는 표지·제목·본문·목록·표를 지원한다. 문서 이력, 승인, 목차,
구분 페이지의 고급 구성은 추가 슬롯 명세와 별도 검증이 필요하다.

스킬은 v8 Core의 내장 스킬 폴더에 포함된다. 공통 Harness에서도
`Install-ProjectSkill.ps1 -Id jh-company-word -Client Codex`로 프로젝트에
설치할 수 있다. 두 경로는 같은 정본을 사용한다. Python 3.9 이상이 필요하고
Word PDF 출력에는 설치된 Windows Microsoft Word가 필요하다. 자동 설치하지
않으며, 없는 기능을 검증 완료로 표시하지 않는다.

Core 내장본과 프로젝트/개인 설치본이 함께 발견되면 전체 스킬 트리 해시가
같은 복사본만 내장 정본으로 조회한다. 설명 파일이 같아도 실행 도구가 수정된
경우는 중복/변경 오류로 차단하며, 외부 스킬의 검토·등록 조건은 그대로 유지한다.
Orca의 전역 지침이 심볼릭 링크라 설치 안전 장치가 거부하는 경우 링크를 우회해
덮어쓰지 않는다. 프로젝트 전용 `--codex-home` 저장소를 만들고 프로젝트 지침에서
해당 CLI 경로와 저장소를 명시할 수 있다. 이 방식은 실제 계정의 인증을 복사하지
않으며 별도 저장소의 `start`에 대한 로그인·모델 실행 검증과 구분해야 한다.

## 패치와 설치 절차

별도 기능 브랜치에서 일반 코드와 합성 테스트만 변경한다. 원본은 읽기 전용으로
분석하고 개인 프로필로 캡처한다. 합성 양성·음성 검사, 독립 코드 검토, 실제
로컬 Word 예제 검증을 거친다. PR의 Windows/Linux CI가 통과한 정확한 HEAD만
병합한다. 고정된 병합 소스에서 프로젝트 스킬과 개인 프로필을 설치하고, 설치
경로의 도구로 다시 생성·검증한다. 기존 지침·스킬·로그인 설정은 보존한다.

되돌리기는 이번 설치가 소유한 스킬/바인딩만 대상으로 한다. 설치 전 해시와
백업을 남기고, 현재 바이트가 설치 기록과 다르면 자동 덮어쓰기·삭제를 중단한다.
Core 자체 설치/해제는 기존 `core/setup.mjs`의 관리 블록 및 복원 절차를 쓴다.
개인 프로필과 사용자가 작성한 결과 문서는 해제 시에도 보존한다.

## 검증과 품질 평가

자동 구조 검사는 원본/결과 해시, XML·관계, 패키지 항목, 수정하지 않은 부품,
페이지 설정과 표 너비를 확인한다. 잘못된 입력, 원본 변조, 기존 결과 덮어쓰기,
숨은 업무 문구와 활성 콘텐츠는 실패해야 한다. 합성 CI는 실제 회사 양식을
대체하지 않으며, CI 머신에 Word가 없으면 Word 검증을 했다고 하지 않는다.

실제 Word에서 열기·필드 갱신·PDF 출력을 하고 최종 페이지를 모두 시각 검토한다.
읽기 전용 출력은 필드를 메모리에서 갱신하며 DOCX 캐시에 저장하지 않는다.
캐시까지 저장한 최종본이 필요하면 별도 Word 저장본을 다시 검증하고 새 해시로
기록한다. `STRUCTURAL_PASS_VISUAL_REQUIRED`는 최종 품질 통과가 아니다.

평가표는 원본 충실도 30, 무결성 25, 배치·가독성 20, 내용 정확성 15,
재사용·설치 10점이다. 90점 이상이고 치명 오류가 없어야 합격이다. 미검증 항목은
점수를 주지 않는다. 점수는 검토 기준이며 향후 무결함 확률이 아니다. 새 세션의
자연어 자동 선택과 실제 모델 행동은 설치된 파일의 존재와 별도 근거로 판단한다.

## 버전 해석

공개 Windows 제품 프리릴리스 `v8.0.0-alpha.1`, 내부 Core 버전
`8.0.0-core-beta.1`, 공통 정책 런타임 `7.0.0`, 기존 프로젝트의 `5.1`
연결은 서로 다른 계층이다. 한 숫자로 합쳐 표시하지 않는다. 회사 Word 기능을
main에 병합해도 이미 공개된 Alpha 태그·첨부 설치 파일이 바뀌지는 않는다.
해당 파일은 기존 고정 소스를 사용한다. 최신 패치의 소스/설치 커밋을 기록한다.
설치 및 문서 테스트의 통과는 Alpha의 정식 운영 준비 완료, OS 명령 통제,
실제 모델 로그인·개발 동작 또는 모든 향후 문서의 무결함을 보장하지 않는다.
