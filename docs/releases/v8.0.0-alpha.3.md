# J Harness v8.0.0-alpha.3 — 프로젝트 이동형 설치

Windows x64 / PowerShell 5.1+용 GitHub Pre-release입니다. 실제 Core는 `8.0.0-core-beta.1`, 이동형 어댑터는 `1.0.0`, 번들 Node는 `22.22.2`입니다. 제품 버전은 루트 `J_HARNESS_VERSION`이 소유하고, 기존 `HARNESS_VERSION`·정책 manifest·index의 `7.0.0`은 26개 정책의 출처 계약으로 유지합니다. 정식 v7과 기존 Alpha2의 태그·첨부파일은 수정하지 않습니다.

## 기본 설치

[고정 릴리스](https://github.com/hacker943410-debug/ai-harness/releases/tag/v8.0.0-alpha.3)에서 설치 스크립트 또는 `J_Harness_v8.0.0-alpha.3_Windows_x64.zip`과 `SHA256SUMS.txt`를 받습니다. 현재 배포용 스크립트는 다음 경로입니다.

```powershell
$u = 'https://raw.githubusercontent.com/hacker943410-debug/ai-harness/main/scripts/Install-JHarnessFromGitHub.ps1'
Invoke-WebRequest -Uri $u -OutFile .\JHarness-Install.ps1
Get-Content .\JHarness-Install.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\JHarness-Install.ps1 -Action Plan -ProjectPath 'C:\Projects\MyProject'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\JHarness-Install.ps1 -Action Install -ApproveInstall -ProjectPath 'C:\Projects\MyProject'
```

기본 동작은 `Plan`이며 설치하지 않습니다. 사용자가 설치를 요청했다면 해당 승인을 `-ApproveInstall`로 전달할 수 있습니다. 저장소의 `Install-JHarness.cmd`도 같은 Windows PowerShell 설치기를 호출합니다. `releases/latest`의 정식 v7을 v8 대신 선택하지 않으며, 다운로드·해시·런타임 검증에 실패하면 중단합니다.

ZIP을 받은 경우 새 폴더에 풀고 로컬 설치기를 사용합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-JHarnessLocal.ps1 -Action Plan -ProjectPath 'C:\Projects\MyProject'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-JHarnessLocal.ps1 -Action Install -ApproveInstall -ProjectPath 'C:\Projects\MyProject'
```

설치 후 선택한 프로젝트에서 `JHarness.cmd status`와 `JHarness.cmd doctor`를 실행합니다. 실제 Core 버전과 `READY_LOCAL`, 런타임 무결성을 확인합니다. 실행 파일은 `.agents/j-harness`, 변경 가능한 작업 기록은 `.jh-artifacts/j-harness-core`에 있습니다. 시스템 Node·Git·Codex·글로벌 Codex 프로필은 필요하지 않습니다. ZIP을 받은 뒤 설치와 로컬 런타임 실행에는 네트워크가 필요하지 않습니다. 모델 서비스 호출이나 외부 도구 설치는 각각 별도 작업입니다.

## 기존 환경과 전환

사용자 지침·인증·PATH와 기존 프로젝트 작업 기록을 보존합니다. `.ai` 바인딩과 관리 블록이 충돌하거나 실행 파일 무결성이 깨졌다면 강제 삭제나 v7 전환 없이 원인을 검토합니다. 진행 중 개발·데이터 변환·운영 배포는 기존 checkpoint·이관·회귀 검증 절차를 유지해야 합니다.

Alpha2 방식의 글로벌 프로필 연결이 명시적으로 필요한 경우에만 공개 설치기의 `-Mode Profile`을 사용합니다. 이 경로는 보존된 Alpha2 설치기로 위임하며 [Alpha2 전환·제거 안내](v8.0.0-alpha.2.md)를 따릅니다. 이동형 설치는 기존 글로벌 연결을 자동 해제하거나 대체하지 않습니다. 정책 소스 자체가 필요한 경우에만 기존 `install.ps1`·프로젝트 정책 연결 절차를 별도로 선택합니다.

회사 Word 스킬과 동일한 native/builtin Skill의 전체 해시 비교 동작을 유지합니다. 개인 원본·로고·프로필·업무 파일은 공개 패키지에 포함하지 않습니다. 자체 Word 프로필은 별도로 준비해야 하며, Python·Microsoft Word 등 문서 생성·렌더링 조건은 [회사 Word 안내](../core/COMPANY_WORD_PROFILE_KO.md)를 따릅니다.

## 검증과 적용 범위

배포 검증 기록과 SHA-256은 릴리스 첨부 자료로 제공합니다. 로컬 검증에는 실제 실패·수정·재검증, stale PASS 차단, 명시적 검증 범위, canonical 프로젝트 모드, Windows 경로 별칭, 손상·누락·링크 거부, 글로벌 API 회귀, 회사 Word/native Skill 탐색과 새 환경 설치를 포함합니다. 같은 소스의 반복 빌드는 ZIP 경로 순서와 타임스탬프를 고정하여 비교할 수 있습니다.

`SHA256SUMS.txt`와 프로젝트 manifest pin은 무결성 근거이며 발행자 디지털 서명은 아닙니다. `READY_LOCAL`은 로컬 준비 상태만 나타냅니다. OS 수준의 보안 강제, 실제 로그인·모델 행동, 다른 물리 PC에서의 사용, 운영 배포와 사용자 최종 검증은 각각 별도 근거가 필요합니다. Beginner Mode와 실제 명령 근거·독립 검토 경계를 유지합니다.
