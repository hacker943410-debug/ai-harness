# J Harness 8.2.1 Windows x64

처음 개발하는 사용자도 Windows 프로젝트에 J Harness를 설치하고, 사용하는 AI CLI 한 가지로 환경 준비부터 구현, 실제 테스트, 실행 방법 확인까지 진행할 수 있습니다.

## Alpha 3부터의 변경

| 버전 | 변경 내용 |
|---|---|
| `8.0.0-alpha.3` | Windows 이동형 설치를 공개했습니다. 버전과 ZIP 해시를 고정하고, 번들 Node와 Core `8.0.0-core-beta.1`, 정책, Skills를 프로젝트에 연결했습니다. |
| `8.1.0` | 초기 환경 점검과 초보자용 첫 작업 안내를 추가했습니다. 작업·검증 기록을 실행 ID로 연결하고, 런타임이나 소스가 바뀌면 이전 통과 기록을 무효화합니다. Windows에서 따옴표·공백·한글 경로를 처리하고, Alpha 3 프로젝트의 업데이트와 복구를 지원합니다. |
| `8.2.0` | `connect claude`로 기존 `CLAUDE.md`를 보존하면서 `AGENTS.md` 연결을 추가합니다. `doctor`가 누락되거나 가려진 지침을 진단합니다. Node `22.23.5` 보안 패치, 안내서 무결성 검사, Node 시작 옵션 격리와 민감한 검증 출력 마스킹을 반영했습니다. `8.1.0` 업데이트 경로를 추가했습니다. |
| `8.2.1` | 설치 후 첫 `quickstart`에서 실행 파일을 찾은 CLI를 먼저 표시합니다. 사용자가 고른 CLI만 프로젝트에 저장하며, 이후에는 해당 CLI의 설치·연결·첫 요청을 안내합니다. `8.2.0`에서의 업데이트와 복구를 추가했습니다. |

`8.1.0`과 `8.2.0`은 이 변경 이력에 포함된 로컬 검증 버전입니다. 제품과 Core 버전은 `8.2.1`이며 26개 공통 정책의 출처 버전은 `7.0.0`입니다.

## 설치하고 첫 작업 시작하기

Windows x64와 PowerShell 5.1 이상에서 ZIP을 풀고 패키지 폴더에서 실행합니다.

```powershell
.\Install-JHarness.cmd -ProjectPath 'C:\Projects\MyProject' -ApproveInstall
Set-Location 'C:\Projects\MyProject'
.\JHarness.cmd quickstart
```

목록에 나온 `.\JHarness.cmd select codex`, `.\JHarness.cmd select claude`, `.\JHarness.cmd select agy` 중 하나를 실행합니다. Claude 연결 안내가 나오면 `.\JHarness.cmd connect claude`를 실행합니다. 로그인은 선택한 CLI에서 진행합니다. 다음번부터 `quickstart`가 저장된 선택을 사용합니다.

기존 프로젝트를 업데이트하려면 프로젝트의 CLI 세션과 진행 중인 작업을 마친 뒤 새 ZIP을 별도 폴더에 풉니다. 그 폴더에서 계획을 확인하고 적용합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-JHarnessLocal.ps1 -Action Plan -Upgrade -ProjectPath 'C:\Projects\MyProject'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-JHarnessLocal.ps1 -Action Install -Upgrade -ApproveInstall -ProjectPath 'C:\Projects\MyProject'
```

중단 후 복구가 필요한 경우 같은 패키지에서 `-Action Recover -Upgrade -ApproveInstall`을 사용합니다. 위 실행 정책 옵션은 해당 PowerShell 프로세스에만 적용됩니다. 설치기는 지원하는 배포본의 해시를 확인하고 작업 기록과 사용자 파일을 보존합니다. 파일 충돌이나 진행 중인 작업이 있으면 변경 전에 상태를 표시합니다. [이동형 사용 안내](../../core/portable/PORTABLE.md)

## 확인한 범위

- 8.2.1 로컬 회귀 테스트에서 53건 통과, 실패 0건, Windows 링크 생성 환경 제약으로 3건 건너뜀.
- Windows PowerShell 5.1에서 시스템 Node와 글로벌 프로필 없이 새 설치, CLI 선택 저장, 첫 예제 앱의 실패·수정·재검증·인계, Alpha 3 업그레이드와 복구를 확인했습니다. 검증한 8.2.0 패키지에서 업그레이드하고 중단 상황을 모의한 뒤 복구·재설치해도 저장된 선택이 유지됐습니다.
- 8.2.0에서 실제 Codex 응답으로 지침 로딩을 확인했습니다. Claude Code와 AGY는 실제 CLI가 로컬 모의 서버에 보낸 요청을 검사했습니다. 두 CLI의 실제 클라우드 모델 응답과 별도 물리 PC 사용은 미검증입니다.
- 일반 이동형 설치는 프로젝트 지침, 로컬 작업과 검증 기록을 관리합니다. CLI 로그인 및 명령 실행 권한은 해당 CLI와 OS 설정에서 관리합니다.

번들 Node 보안 수정 범위는 [Node.js 22.23.5 릴리스](https://nodejs.org/en/blog/release/v22.23.5)를 참고하세요.
