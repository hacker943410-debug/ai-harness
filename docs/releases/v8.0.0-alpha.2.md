# J Harness v8.0.0-alpha.2 — 회사 Word 스킬 통합

배포일: 2026-11-09. Windows x64 Alpha / GitHub Pre-release. 내부 Core `8.0.0-core-beta.1`, 공통 정책 `7.0.0`. 기존 `alpha.1` 및 정식 `v7.0.0` 태그·첨부파일은 보존합니다.

## 변경 사항

- `jh-company-word`: 개인 DOCX 원본에서 페이지·스타일·표·머리말·꼬리말을 보존하는 문서 작성 절차와 생성·검증 도구.
- Core와 native 위치에 동일한 스킬이 있어도 전체 파일 해시가 일치하면 정본 builtin을 읽습니다. 내용이 다른 중복 스킬은 계속 차단합니다.
- PowerShell 설치 소스를 PR #13·#14가 병합된 `a882c02f46905237e8fd843a7ca66c0ea1322fe3`으로 고정했습니다. ZIP은 릴리스 태그의 소스로 만듭니다. 두 경로의 회사 Word 스킬·실행 코드 일치 여부를 확인합니다.
- 회사 원본·로고·프로필·업무 결과물은 배포하지 않습니다. 이 PC의 개인 프로필은 설치 폴더 밖에 보관하며, 다른 PC에서는 자체 참조 DOCX로 프로필을 준비해야 합니다. [프로필 구성과 품질 검증](../core/COMPANY_WORD_PROFILE_KO.md).

## 설치

[릴리스](https://github.com/hacker943410-debug/ai-harness/releases/tag/v8.0.0-alpha.2)에서 `JHarness-Install-Alpha.ps1` 또는 `J_Harness_v8.0.0-alpha.2_Windows_x64.zip`을 받습니다. `SHA256SUMS.txt`는 배포 파일 해시이며 발행자 디지털 서명은 아닙니다.

고정 릴리스 설치 명령:

```powershell
$u = 'https://github.com/hacker943410-debug/ai-harness/releases/download/v8.0.0-alpha.2/JHarness-Install-Alpha.ps1'
Invoke-WebRequest -Uri $u -OutFile .\JHarness-Install-Alpha.ps1
Get-Content .\JHarness-Install-Alpha.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\JHarness-Install-Alpha.ps1 -Action Plan
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\JHarness-Install-Alpha.ps1 -Action Install
```

앞으로의 현재 배포용 스크립트는 저장소 첫 화면에 있는 `main/scripts/Install-JHarnessFromGitHub.ps1` 주소에서 받습니다. 위 버전 고정 URL과 기존 `alpha.1` 파일은 다음 릴리스가 나와도 바뀌지 않습니다. `releases/latest`는 기존 정식 v7 채널이므로 v8 Alpha 선택에 사용하지 않습니다.

ZIP은 새 폴더에 풀고 `J_Harness_Install.cmd`를 실행합니다. 두 경로 모두 Node 22.22.2를 앱 전용으로 제공하며, 기존 native Codex가 없을 때 공식 Codex 0.166.0 바이너리를 약 372 MB 내려받아 해시를 확인합니다. 기존 Codex가 있으면 이를 재사용합니다. 기존 인증은 보존하고, 필요한 로그인은 공식 Codex 화면에서 직접 수행합니다.

`-ExecutionPolicy Bypass`는 실행 프로세스에만 적용합니다. 조직 정책으로 실행이 차단되면 중단합니다.

## 기존 Alpha에서 전환

현재 설치기는 기존 설치를 발견하면 `PRODUCT_ALREADY_EXISTS_REVIEW_OR_UNINSTALL_FIRST` 또는 `EXISTING_CORE_REVIEW_REQUIRED_DO_NOT_REPLACE`로 중단합니다. 내부 Core 버전 문자열이 같다는 이유로 기존 `setup update`의 `ALREADY_CURRENT`를 최신 패치 확인으로 해석하면 안 됩니다.

1. 기존 설치 위치와 CodexHome을 확인하고 진행 중 세션을 종료합니다. 바꾼 관리 파일이 있으면 보존·검토합니다.
2. 기존 `%LOCALAPPDATA%\JHarness-Bootstrap\J_Harness_Remove.cmd`를 실행하고 `UNLINKED_AND_ORIGINAL_GUIDANCE_RESTORED`를 확인합니다. 사용자 지침·인증·관리 밖의 파일은 덮어쓰지 않으며 이전 Core와 백업은 보존합니다. 제거가 충돌로 중단되면 수동 강제 삭제 대신 원인을 해결합니다.
3. 새 설치 명령을 실행합니다. 경로를 지정했던 경우 동일한 `-CodexHome` 및 `-ManagedRoot`를 사용합니다. 일반 Core만 설치한 경우 해당 Core의 제거 절차를 먼저 사용합니다.
4. `J_Harness_Doctor.cmd`에서 `CONNECTED_FOR_NEW_SESSIONS`와 빈 `runtimeDrift`를 확인하고 새 세션을 시작합니다. `runtime/core/cli.mjs skills read jh-company-word --codex-home <home> --project <project>`가 `BUILTIN`을 반환하는지 확인합니다.

개인 Word 프로필은 설치 폴더 밖에 유지합니다. 이 전환은 Alpha의 검증된 제거·재설치 절차이며 안전한 무인 자동 업그레이드 기능을 뜻하지 않습니다.

## 검증과 제한

회사 Word의 38개 Python 테스트, 4개 패키징·탐색 테스트 및 Windows 실제 설치 후 builtin 스킬 조회를 릴리스 검증에 사용합니다. 배포 ZIP과 PowerShell 경로는 격리된 CodexHome에서 설치·진단·스킬 읽기·제거·원본 지침/인증 바이트 보존을 확인합니다. 실행 기록과 해시는 릴리스 첨부 검증 자료에 남깁니다.

Word 문서의 구조 검사와 실제 Word 페이지 검토는 별도입니다. Word 문서 생성에는 Python 3.9+가 필요하고, Word COM 렌더링에는 설치된 Microsoft Word가 필요합니다. 이 문서 도구를 하네스 설치기가 별도 설치하지 않습니다. 서명된 발행자 인증, OS 수준 Supervisor 강제, 실제 사용자 로그인/모델 작업, Claude/AGY 제품 어댑터, 다른 PC의 글꼴 재현은 이 Alpha의 검증 범위 밖입니다.
